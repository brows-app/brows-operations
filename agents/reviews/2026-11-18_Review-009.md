## Candidates investigated and withdrawn

- **Long cell content widening shared columns.** Row columns share size groups with the header and size as
  Auto. A long name or data value could have widened its column and pushed root commands out of view. A probe
  used a 76-character path as the name, and then as the data, at 1,400, 900, 600, 400, and 300 DIP. The
  pixel header width governed in every case. Name stayed 250 DIP and later narrowed to 233 and 133 DIP.
  Remove ended at the viewport edge, passed hit testing, and `ScrollableWidth` stayed 0.
- **Template reapplied at a narrow stage.** `OnApplyTemplate` no longer applies the column overrides
  immediately, and stage selection keeps the previous stage. With the control at 300 DIP in the narrowest stage,
  a probe cleared and restored `Template`. It then switched to Default and back to Responsive. The new
  columns settled at the same widths as before (50, 133, 0, 0, 0, 0, 0, 17, and 100 DIP), and Remove stayed
  reachable.
- **Paused override clocks keeping the render loop busy.** A probe counted rendering ticks for one second in a
  shown window. It counted 33 ticks for Default at 1,400 DIP, 33 for Responsive at 1,400 DIP, and 32 for
  Responsive at 600 DIP with five columns overridden. The paused clocks added no frame cost.
- **Ignoring nested scroll viewer events.** `OperationListScrollViewer_ScrollChanged` now ignores events whose
  `OriginalSource` is a nested scroll viewer. Those events do not escape the layout checks, because the
  `LayoutUpdated` checks cover inset changes from nested viewers. The `listbox` cases of the existing
  items-template inset test exercise this.

## Optional improvements

- **Layout cost per pass in Responsive mode.** `OperatorControl_LayoutUpdated` calls `RootOperationRowWidth`,
  which walks the entire row tree (`source/Brows.Operations.Windows/Windows/Controls/OperatorControl.cs:225-239`
  and `:197-216`). Each `OperationInlinePanel` also rechecks its ancestors
  (`source/Brows.Operations.Windows/Windows/Controls/OperationInlinePanel.cs:29-46`). WPF raises
  `LayoutUpdated` after every layout pass on the dispatcher, including unrelated passes. A .NET 10 probe timed
  50 unrelated layout passes at 900 by 600 DIP:

  | Root operations | Visuals (Default / Responsive) | Default | Responsive |
  | --- | --- | --- | --- |
  | 25 | 1,242 / 1,918 | 0.33 ms | 0.44 ms |
  | 100 | 4,692 / 7,393 | 0.11 ms | 1.29 ms |

  The cost grows linearly with the rows and stays small at realistic operation counts. Caching the root rows,
  or skipping the walk when no row was measured or arranged since the last check, would remove most of it if
  large operation lists become a requirement.
- **Type name.** `HeaderColumnWidthOverride<T>` now overrides `MinWidth` as well as `Width`
  (`source/Brows.Operations.Windows/Windows/Controls/ResponsiveHeaderColumn.cs:70-71`). A name such as
  `HeaderColumnLayoutOverride<T>` would describe both uses. This is a readability note only.
